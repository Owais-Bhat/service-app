2 Animated Mesh Background

bg-mesh — 4 floating blobs, always behind everything

Animated background (position: fixed; inset: 0; z-index: 0)
CSS: Each blob is a <span> inside .bg-mesh with position:fixed; inset:0; z-index:0; overflow:hidden.
Blobs animate via @keyframes floaty { 0% { transform:translate(0,0) scale(1) } 100% { transform:translate(4vw,5vh) scale(1.15) } } — 22s alternate infinite.
Each blob has a different animation-delay: m1=0s, m2=-4s, m3=-9s, m4=-13s.
Sizes: m1=46vw, m2=40vw, m3=38vw, m4=30vw. Uses filter:blur(60px). Reduced-motion: animation disabled.

6 Entrance Animations

Staggered rise animation on page load

Every element that should animate in gets class .in and an inline CSS variable --d: 0.06s (delay).

CSS rule:
.anim-ready .in { animation: rise 0.55s var(--ease) both; animation-delay: var(--d, 0s); }
@keyframes rise { from { transform: translateY(16px); } to { transform: none; } }

Key rule: Animate TRANSFORM ONLY — never opacity — so content is always visible even if animation is frozen in a backgrounded tab.

Stagger delays used: KPI cards 0, 0.06, 0.12, 0.18s. Charts 0.12, 0.16s. Lists 0.20, 0.24s.

Trigger: document.documentElement.classList.add('anim-ready') is called inside a double requestAnimationFrame on page load so it only fires when the page is genuinely visible.

Reduced motion: @media (prefers-reduced-motion: reduce) { .anim-ready .in { animation: none; transform: none; } }
